扫描器 secwatch

在服务器上运行一次，告诉你哪些软件有已知漏洞、该升级到哪个版本、先修哪个。它是单个静态二进制文件，不需要 Docker、Python 或其他依赖。

  • 只读：不修改系统，不执行任何修复命令。修复命令只打印出来，由你决定是否执行。
  • 不上传：只下载签名的漏洞数据包，所有比对都在本机完成，本站不会收到你的软件清单。
  • 按发行版判断：Debian、Ubuntu 等会把补丁移植到旧版本号里，扫描器使用发行版自己的安全数据，不会因为版本号“看起来旧”而误报。

安装

curl -fsSL https://sec.ly2u.com/install.sh | sh

安装脚本只做三件事：从 GitHub Releases 下载对应 CPU 架构的程序，校验发布签名和 SHA-256，复制到 /usr/local/bin（非 root 时为 ~/.local/bin），并创建短命令 lysec（与 secwatch 完全相同；名字已被其他程序占用时不创建）。签名校验使用 minisign；没有 minisign 时使用 OpenSSL 3。校验失败会直接中止。

想先看脚本内容，可以先下载再运行：

curl -fsSLo install.sh https://sec.ly2u.com/install.sh
less install.sh
sh install.sh

可选环境变量：SECWATCH_VERSION=v0.1.0 安装指定版本；SECWATCH_INSTALL_DIR=/opt/bin 指定安装位置。

手动下载并校验

从 GitHub Releases 下载 secwatch-linux-amd64（或 arm64）、SHA256SUMS 和 SHA256SUMS.minisig，然后：

minisign -Vm SHA256SUMS -P {{ release_key or "（发布公钥，见 keys/release-signing.pub）" }}
sha256sum -c --ignore-missing SHA256SUMS

也可以用 GitHub 的构建来源证明确认程序由本仓库的公开流程构建：gh attestation verify secwatch-linux-amd64 --repo ly2u/sec

更新

漏洞数据每次扫描都会自动获取最新版，不需要为了新漏洞更新程序。程序有新版本时，报告最后会提示一行；在 sudo lysec 菜单里选“更新”，或运行 sudo lysec update。它和安装脚本一样先校验发布签名和 SHA-256、确认新程序能运行，才替换旧版本。程序从不自动更新自己。

定时检查与通知

想让它自己定期检查、有新问题时提醒你？运行 sudo lysec 打开菜单选 3，或者直接：

sudo lysec schedule

按提示填入 Telegram 机器人（或 Webhook 地址），它会先发一条测试消息，确认收到后才开启。默认每 1 小时检查一次（可设 1–720 的整数小时），出现“尽快处理”及以上、或已被在野利用的新问题时立即通知；没修好的每天最多提醒一次，修好后通知“已恢复”。消息只发到你自己的渠道，不经过本站；只提醒，不会自动修复。国内机器连不上 Telegram 时，可以用 --telegram-api 指定自建反代。查看状态：sudo lysec schedule --status；关闭并删除全部配置：sudo lysec schedule --remove。

使用

sudo lysec scan                 # 一屏看完：结论、要处理的软件包、修复命令
sudo lysec scan --pkg openssh   # 只看一个软件包：全部漏洞、升级和验证命令
sudo lysec scan --container db  # 只看一个容器的结果
sudo lysec scan --all           # 完整报告：全部结果、参考链接、说明
sudo lysec scan --format json   # 给脚本和监控用

用 root 运行才能完整检查：哪些服务对公网监听、升级后哪些进程还在使用旧的库、内核是否需要重启。非 root 也能运行，但这几项会缺失。

优先级

P0立即处理：已被确认在野利用（CISA KEV），或严重漏洞且服务对公网开放
P1尽快处理：未来 30 天被利用概率 ≥ 10%（EPSS），或高危漏洞且服务对公网开放
P2有空时处理：其余高危或严重漏洞
P3了解即可：中低危，默认折叠

退出码

想要定时检查并收到 Telegram 通知，用上面的 sudo lysec 菜单即可；退出码便于接入你自己的脚本或监控：0 没有紧急问题；3 有可处理的 P0/P1 问题或已被在野利用的漏洞；1 扫描失败；2 参数错误。

# 自己写 cron 的例子：每天 8 点检查，有紧急问题时写日志
0 8 * * * /usr/local/bin/secwatch scan > /var/log/secwatch.txt 2>&1; [ $? -eq 3 ] && logger -t secwatch "发现需要立即处理的漏洞"

不经软件包安装的软件（宝塔、LNMP 一键包、源码编译、官方二进制、nvm 等）会按程序路径识别版本并对照上游数据，目前支持：{% for slug, rule in products.items() %}{{ rule.name }}{% if not loop.last %}、{% endif %}{% endfor %}。

以 root 运行时还会检查运行中 Docker 容器内的系统软件包（Debian、Ubuntu、Alpine 镜像），通过只读方式读取容器文件，不调用 docker 命令；容器里的漏洞会给出更新镜像的方法。

Go 编译的程序（Caddy、frp、Xray、Alist、docker compose 与 buildx 插件、自己编译的服务等）会读取程序里记录的模块和 Go 版本，对照 Go 官方漏洞库判断，包括只有一个程序的精简容器镜像。程序内置依赖和 Go 标准库的漏洞标为“可能受影响”，因为是否真能被利用取决于程序有没有用到相关功能。

暂不检查：未运行的镜像、RPM 系统的容器、Python/Node 等语言依赖包、Windows 和 macOS。未列出的问题不代表没有漏洞。

自建数据源

数据包是公开的静态文件，可以镜像到内网：lysec scan --bundle-url https://你的地址/bundles。也可以完全离线运行：下载数据包后使用 --offline --bundle 文件。数据包都带有签名，扫描器只接受内置公钥（bundle-signing.pub）签名的数据。
