# 产品规则

每个产品一个 JSON 文件，服务端与扫描器共用。本目录不包含可执行脚本。

扫描器在 `scanner/internal/l2/rules/` 中嵌入一份完全相同的副本（测试会校验两边一致），因此**规则随扫描器代码一起经过审核和发布，不会从服务器下发**。原因：规则决定扫描器去哪个路径找程序、用什么参数运行它。如果由服务器下发，服务器一旦被攻破，攻击者就能指挥所有用户的扫描器运行任意程序。

## 字段

| 字段 | 使用方 | 含义 |
|---|---|---|
| `slug` | 两者 | 产品标识，与文件名一致 |
| `identity.cve_affected` | 服务端 | 在 CVE 记录 `affected[]` 中识别该产品的 `vendor` / `product` 组合（不区分大小写） |
| `detect.binaries` | 扫描器 | 固定路径（可含 `*`）与安装方式：`baota` 宝塔、`lnmp` 一键脚本、`source` 源码编译、`binary` 官方二进制、`nvm` / `fnm` / `volta` / `n` 版本管理器 |
| `detect.process_names` | 扫描器 | 运行中进程的程序名；不属于任何软件包的进程也会被检查 |
| `detect.version_args` | 扫描器 | 读取版本时传入的**固定只读参数** |
| `detect.version_regex` | 扫描器 | 从输出中提取上游版本号（第一个捕获组） |
| `detect.path_version_regex` | 扫描器 | 从路径中提取版本号，用于不能安全执行的程序（如普通用户目录下的 nvm） |
| `detect.bundled` | 扫描器 | 从输出中识别内置的其他组件（如 nginx 静态链接的 OpenSSL） |
| `detect.variants` | 扫描器 | 输出包含特定文字时改判为另一产品（如 `mysqld` 实际是 MariaDB） |
| `detect.packages` | 扫描器 | 第三方软件源中对应的包名或源码包名正则 |
| `upgrade` | 扫描器 | 按安装方式给出的升级指引，`{name}`、`{fixed}` 为占位符 |

## 扫描器的执行安全规则

- 只执行属于 root、且路径上每一级目录都不可被其他用户写入的程序。否则改为从路径读取版本，读不到就判为"无法判定"。
- 不经过 shell，参数固定，超时 5 秒，输出最多读取 64 KB，环境变量清空。
- `--no-exec` 时完全不执行，只使用路径和软件包信息。

## 贡献新产品

提交 PR 时请附上：

1. 官方安全公告或 CVE 记录中该产品的 `vendor` / `product` 写法；
2. 至少一个真实安装路径及 `version_args` 的实际输出样例；
3. 对应的扫描器测试用例（正例与反例）。
